Edge Grammar

A test of an edge-led visual grammar for the HQ workflow canvas: meaning carried by stroke pattern, colour, and arrowhead on the connections, not by where a node happens to sit. Five hand-authored compositions, five different real-world workflow shapes. No layout engine — every position below was placed by hand.

01

Guarded pipeline with multiple outcomes

A linear happy path where three guard steps can each bail to a different named outcome. Failure exits are short local hops to a right-hand outcome column, not long lines down the side of the canvas.

02

Retry to exhaustion

A step that retries itself on transient failure. The loop reads as recoverable (amber, curls back into the same step); running out of attempts reads as final (red, exits to a terminal outcome and never returns).

03

Fork / join parallelism

One step fans out to three concurrent steps that all must complete before a single confirm step runs. The diamond shape itself is the information: these three run at once.

04

Sync → async handoff

The request validates, enqueues a job, and returns to the user immediately. A background worker keeps going after that response. The dotted blue edge is the one moment work crosses from foreground to background — everything after it lives in a visually separate zone.

05

Failure with cleanup

A failure doesn't jump straight to a terminal — it runs a compensation step first. The trigger is a dashed red edge with a reason; the cleanup step's own exit is a plain solid edge, because by that point what happens next is guaranteed, not conditional.

Static design mockup — hand-authored inline SVG, no layout engine, no React Flow, no dagre. Positions were chosen by hand for maximum clarity on each of five workflow shapes.
