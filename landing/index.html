04 / Honest failure

When the agent stumbles, the map doesn't.

Agents write partial JSON. Schemas get violated. It happens mid-keystroke, mid-refactor, mid-everything. HQ's answer is last-valid-state preservation: the last good map stays on screen, marked stale, while a precise diagnostics file tells the agent exactly how to repair what it broke.

  • a
    Errors are sentences, not stack traces.
    Every issue carries a JSON pointer, a human-readable message, and a hint.
  • b
    The loop closes itself.
    Agents read diagnostics.json after every write and fix what they introduced.
  • c
    The board never blanks out.
    A workflow that was once valid stays rendered until a newer valid version replaces it.

05 / Principles

An instrument, not a chatbot.

01

Local-first

Renders from files on disk. No accounts, no telemetry, no runtime network calls beyond localhost. Your code never leaves the machine.

offline by construction
02

No LLM inside

HQ contains no model and no prompts. Your agent is the brain; HQ is the instrument that keeps it honest.

bring your own agent
03

Agent-proof schema

Strict Zod schemas reject invented fields — especially visual ones. Layout, colour and typography are computed by HQ, never authored by a model.

semantics in, pixels out
04

Last-valid-state

A half-written file never blanks the board. The last valid map stays on screen while diagnostics guide the repair.

failures stay legible
